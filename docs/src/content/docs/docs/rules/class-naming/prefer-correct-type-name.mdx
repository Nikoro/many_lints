This rule flags a class, mixin, enum, extension type or typedef whose name is too short, too long, or does not start with a capital letter.

The SDK's [`camel_case_types`](https://dart.dev/tools/linter-rules/camel_case_types) covers the *spelling* of a type name but says nothing about its length, and length is where the two real failures live: a one-letter type (`class R`) that reads as a type *parameter* at the point of use, and a forty-character type that names its whole call chain instead of the thing it models.

The defaults are deliberately loose — 3 to 40 characters — so the rule reports only genuine outliers.

This rule is in the **`pedantic`** preset, because the right length is a house style.

## Why use this rule

A type name is the single most-read identifier in a codebase: it appears in every declaration, every parameter list and every error message. A name that is too short forces the reader to jump to the declaration to learn anything; a name that is too long is usually a sign the type is doing several jobs, and the name is the list of them.

Type **parameters** are exempt. `T`, `E` and `K`/`V` are the convention the SDK itself uses, and holding them to a minimum length would fight it.

**See also:** [Effective Dart: naming](https://dart.dev/effective-dart/design#names), [`camel_case_types`](https://dart.dev/tools/linter-rules/camel_case_types)

## Don't

```dart
// Reads as a type parameter at the point of use.
class Ab {}

// Names its whole call chain rather than the thing it models.
class AVeryLongTypeNameThatDescribesItsEntireCallChain {}
```

## Do

```dart
class UserRepository {}

// A type PARAMETER is exempt — this is the SDK's own convention.
class Box<T> {
  final T value;

  Box(this.value);
}
```

## Options

<Tabs syncKey="many-lints-config-file">
<TabItem label="analysis_options.yaml">

```yaml
# analysis_options.yaml
many_lints:
  rules:
    prefer_correct_type_name:
      min_length: 4
      max_length: 32
      ignored_names: [Id, Db]
```

</TabItem>
<TabItem label="many_lints.yaml">

```yaml
# many_lints.yaml
rules:
  prefer_correct_type_name:
    min_length: 4
    max_length: 32
    ignored_names: [Id, Db]
```

</TabItem>
</Tabs>

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `min_length` | int | `3` | Shortest accepted name, excluding a leading underscore |
| `max_length` | int | `40` | Longest accepted name, excluding a leading underscore |
| `ignored_names` | list of strings | `[]` | Names exempt from every check |

## Turning this rule off

To disable this rule:

```yaml
plugins:
  many_lints:
    diagnostics:
      prefer_correct_type_name: false
```

To keep the rule on but skip certain paths, use [per-rule `exclude`](/many_lints/docs/configuration/#excluding-paths-per-rule).
