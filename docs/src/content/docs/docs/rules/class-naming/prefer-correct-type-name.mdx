Flags a class, mixin, enum, extension type or typedef whose name is too short, too long, or does not start with a capital letter.

The SDK's [`camel_case_types`](https://dart.dev/tools/linter-rules/camel_case_types) covers the *spelling* of a type name but says nothing about its length. The defaults are deliberately loose — **3 to 40 characters** — so the rule reports only genuine outliers.

This rule is in the **`pedantic`** preset, and works with its defaults — no configuration needed.

## Don't

```dart
// Two characters: reads as a type PARAMETER at the point of use.
class Ab {}

// 48 characters: names its whole call chain rather than the thing it models.
class AVeryLongTypeNameThatDescribesItsEntireCallChain {}
```

## Do

```dart
class UserRepository {}

class OrderTotal {}
```

## Examples

### Every type declaration is checked, not just classes

Mixins, enums, extension types and typedefs go through the same bounds:

```dart
// Don't
mixin Ab {}                     // LINT
enum Cd { a }                   // LINT
typedef Ef = int;               // LINT

// Do
mixin Cacheable {}
enum OrderStatus { open }
typedef UserId = int;
```

### Type parameters are exempt

`T`, `E` and `K`/`V` are the SDK's own convention, so a single-letter type *parameter* is never reported — only the declaration it sits on:

```dart
// Accepted — `T` is a type parameter, `Box` is 3 characters
class Box<T> {
  const Box(this.value);

  final T value;
}
```

### A private type is measured without its underscore

The leading `_` is a modifier, not part of the name, so `_Foo` counts as three characters and passes the default `min_length: 3`:

```dart
// Accepted
class _Foo {}
```

### Tightening the bounds

Raise `min_length` when three characters is still too terse for your codebase, and lower `max_length` to force long names to be broken up. `ignored_names` exempts the abbreviations you keep on purpose:

<Tabs syncKey="many-lints-config-file">
<TabItem label="analysis_options.yaml">

```yaml
# analysis_options.yaml
many_lints:
  rules:
    prefer_correct_type_name:
      min_length: 4
      max_length: 32
      ignored_names: [Id, Db]
```

</TabItem>
<TabItem label="many_lints.yaml">

```yaml
# many_lints.yaml
rules:
  prefer_correct_type_name:
```

```dart
// Accepted only because they are in `ignored_names`
class Id {}
class Db {}

// Reported under `min_length: 4`, accepted under the default 3
class Box {}
```

## Options

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `min_length` | int | `3` | Shortest accepted name, excluding a leading underscore |
| `max_length` | int | `40` | Longest accepted name, excluding a leading underscore |
| `ignored_names` | list of strings | `[]` | Names exempt from every check, matched exactly including any underscore |

## Known limitations

**Extensions are not checked.** A named `extension` declaration goes through neither bound.

**Capitalisation overlaps the SDK.** A lowercase type name is already reported by [`camel_case_types`](https://dart.dev/tools/linter-rules/camel_case_types); this rule reports it too, so you will see both when that lint is on.

**See also:** [Effective Dart: naming](https://dart.dev/effective-dart/design#names)

## Turning this rule off

To disable this rule:

```yaml
# many_lints.yaml
rules:
  prefer_correct_type_name: false
```

To keep the rule on but skip certain paths, use [per-rule `exclude`](/many_lints/docs/configuration/#excluding-paths-per-rule).
