Flags explicit constructor invocations of `EdgeInsets`, `BorderRadius`, `Radius`, and `Border` in argument or collection-literal position. In those positions the class name is usually redundant and can be replaced with a dot shorthand like `.all()`, `.symmetric()`, or `.circular()`.

## Why use this rule

These Flutter classes appear frequently in widget trees, and their constructors are often passed as named arguments where the type is already known. Replacing `EdgeInsets.all(8)` with `.all(8)` reduces visual clutter in deeply nested build methods, making the widget tree easier to scan.

**See also:** [Dart language - Constructor tear-offs](https://dart.dev/language/constructors#constructor-tear-offs)

## Don't

```dart
Widget priceTag() => Padding(
  padding: EdgeInsets.symmetric(horizontal: 20, vertical: 6),
  child: Container(
    decoration: BoxDecoration(
      borderRadius: BorderRadius.circular(10),
      border: Border.all(color: Color(0xFF2196F3), width: 3),
    ),
    child: Text('12.99'),
  ),
);
```

## Do

```dart
Widget priceTag() => Padding(
  padding: .symmetric(horizontal: 20, vertical: 6),
  child: Container(
    decoration: BoxDecoration(
      borderRadius: .circular(10),
      border: .all(color: Color(0xFF2196F3), width: 3),
    ),
    child: Text('12.99'),
  ),
);
```

## Known limitations

In argument position the rule reads the declared type of the receiving parameter, because that is what a dot shorthand resolves against. It reports only when that type is the constructed class, or declares a constructor or static method of the same name. `EdgeInsets.all(8)` passed to an `EdgeInsetsGeometry` parameter is reported, since `EdgeInsetsGeometry.all` exists. These are not reported:

```dart
// ShapeBorder is abstract, so `.new()` would not compile here.
ExpansionTile(shape: const Border(), title: Text('Details'));

// A dynamic parameter gives a shorthand nothing to resolve against.
void log(dynamic value) {}
void caller() => log(EdgeInsets.all(8));
```

## Turning this rule off

This rule is in the **`opinionated`** preset, so it is on with
`preset: opinionated`, or by name:

```yaml
# many_lints.yaml
rules:
  prefer_shorthands_with_constructors: true
```

To turn it off again:

```yaml
# many_lints.yaml
rules:
  prefer_shorthands_with_constructors: false
```

To keep the rule on but skip certain paths, use [per-rule `exclude`](/many_lints/docs/configuration/#excluding-paths-per-rule).

## Options

<Tabs syncKey="many-lints-config-file">
<TabItem label="analysis_options.yaml">

```yaml
# analysis_options.yaml
many_lints:
  rules:
    prefer_shorthands_with_constructors:
      classes: [EdgeInsets, BorderRadius]
      additional_classes: [Alignment, TextStyle]
```

</TabItem>
<TabItem label="many_lints.yaml">

```yaml
# many_lints.yaml
rules:
  prefer_shorthands_with_constructors:
    classes: [EdgeInsets, BorderRadius]
    additional_classes: [Alignment, TextStyle]
```

</TabItem>
</Tabs>

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `classes` | list of strings | `[EdgeInsets, BorderRadius, Radius, Border]` | **Replaces** the default class list outright |
| `additional_classes` | list of strings | `[]` | **Extends** whichever list applies |

Use `additional_classes` when you want the defaults plus your own — restating
every default in `classes` means your config silently misses any class added in
a later release. Set `classes: []` to disable the rule for all classes (though
`enabled: false` is clearer for that).

Common additions: `Alignment`, `AlignmentDirectional`, `EdgeInsetsGeometry`, `TextStyle`.
