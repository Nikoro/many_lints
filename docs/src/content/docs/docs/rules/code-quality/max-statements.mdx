This rule flags a function that executes more statements than the configured budget.

## Why use this rule

This is the counterpart to [`avoid_long_functions`](/many_lints/docs/rules/code-quality/avoid-long-functions/), measuring what a function *does* rather than how much room it takes. The two disagree in exactly the useful cases: a function of twenty short statements is long by both measures, while one holding a single wide widget tree is long by lines only, and splitting it would help nobody.

Statements are counted through nested blocks, so a loop body counts toward the function that owns it. A nested function expression is counted on its own — a callback is separate work, not more of the enclosing function's.

This rule is in the **`pedantic`** preset: a budget is a house style, and the right number differs per codebase.

## Don't

With `max_statements: 5`:

```dart
void handleSubmit(String email, String password) {
  final trimmedEmail = email.trim();
  final trimmedPassword = password.trim();
  final emailValid = trimmedEmail.contains('@');
  final passwordValid = trimmedPassword.length >= 8;
  final ready = emailValid && passwordValid;
  print(ready); // LINT: 6 statements exceeds the budget of 5
}
```

## Do

Give each step a name and the caller reads as a summary:

```dart
void handleSubmit(String email, String password) {
  final credentials = _validate(email, password);
  if (credentials == null) return;
  _submit(credentials);
}

({String email, String password})? _validate(String email, String password) {
  final trimmedEmail = email.trim();
  if (!trimmedEmail.contains('@')) return null;
  if (password.length < 8) return null;
  return (email: trimmedEmail, password: password);
}

void _submit(({String email, String password}) credentials) {}
```

## Enabling this rule

This rule is in the **`pedantic`** preset, so it is enabled by `preset: pedantic` or by name:

```yaml
# many_lints.yaml
rules:
  max_statements:
    enabled: true
```

| `max_statements` | int | `25` | How many statements a function may execute |

## Turning this rule off

To disable this rule:

```yaml
# many_lints.yaml
rules:
  max_statements: false
```

To keep the rule on but skip certain paths, use [per-rule `exclude`](/many_lints/docs/configuration/#excluding-paths-per-rule).
