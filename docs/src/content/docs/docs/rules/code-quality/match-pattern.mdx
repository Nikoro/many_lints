Reports code matching a pattern the project supplies, and offers the project's own replacement as a quick fix.

This rule is in **no preset**. It reports nothing until you configure `patterns:`.

## Why use this rule

Every project accumulates conventions that no general-purpose lint will ever ship:

- "use our `Clock` seam, not `DateTime.now()`"
- "use our trailing `.unawaited()`, not the SDK free function"
- "use `context.theme`, not `Theme.of(context)`"
- "this deprecated helper moved, call the new one"

Today each of those lives in a `grep` in a pre-commit hook: no fix, no IDE integration, no `// ignore:` support, and no idea where an expression begins or ends. This rule gives a one-off convention the same ergonomics as a built-in lint, a squiggle where the problem is and a lightbulb that fixes it.

It also relieves pressure on this package. Several `banned_*` rules exist only because the vocabulary is project-specific; a generic matcher covers the long tail without a new rule per idea.

## Don't

```dart
unawaited(repository.refresh());
```

## Do

```dart
repository.refresh().unawaited();
```

## How matching works

The pattern is matched against the **source text of one AST node**, named by `node:`. Matching a node rather than a raw line is what bounds the match: a pattern cannot run past the end of the expression it was written for.

| `node:` | Matches | Example |
|---------|---------|---------|
| `methodInvocation` (default) | A call | `unawaited(x)`, `DateTime.now()`, `Theme.of(context)` |
| `propertyAccess` | A property read with no argument list | `Theme.of(context).textTheme` |

`propertyAccess` exists for replacements whose right-hand end is a property rather than a call. With `methodInvocation` alone the matched node stops at `Theme.of(context)` and the trailing `.textTheme` cannot be rewritten with it.

Patterns are anchored to the whole node, so `find: 'awaited\(1\)'` does **not** match `unawaited(1)`. A `$` inside a `find:` needs escaping in YAML the same as anywhere else.

Two consequences of matching text follow from the design, and both are deliberate:

- **No type information.** `unawaited` from any library looks the same, so a pattern cannot tell the SDK's function from your own helper of that name.
- **Formatting matters.** A call split across lines will not match a pattern written on one.

## The replacement

`replace:` is a template over the capture groups of `find:`. `$1`..`$9` expand to groups, `$0` to the whole match, and `$$` is a literal `$`. A group that did not participate expands to the empty string.

`replace:` is optional. **Omitting it is how an entry says "report only"** — nothing is ever rewritten unless you asked for it.

Because the template is unreviewed configuration rather than a shape this package understands, the fix is held to guard rails the hand-written fixes do not need:

1. **Parsed before offering.** If applying the template produces source that does not parse, the fix is dropped and the diagnostic is left alone. A wrong pattern cannot turn working code into a syntax error.
2. **Never bulk-applied.** The fix is `singleLocation`, so `dart fix --apply` will not sweep a hand-written regex across your project.
3. **Nothing checks scope.** A replacement naming a symbol that is not imported produces code that parses but does not compile. That one is yours to get right.

An invalid regex, or a `node:` naming no known kind, drops that entry rather than throwing — the same as every other malformed option, because a plugin cannot report diagnostics against a YAML file.

## Configuration

<Tabs syncKey="many-lints-config-file">
<TabItem label="analysis_options.yaml">

```yaml
# analysis_options.yaml
many_lints:
  rules:
    match_pattern:
      patterns:
        - find: '^unawaited\((.+)\)$'
          replace: '$1.unawaited()'
          message: 'Prefer the trailing form from many_extensions.'
          in: ['lib/**']
```

</TabItem>

## Options

| Option | Type | Default | Description |
|--------|------|---------|-------------|
| `patterns` | list of entries | `[]` | The patterns to match. Each entry takes `find`, and optionally `replace`, `node`, `message` and `in` |

Per entry:

| Key | Type | Default | Description |
|-----|------|---------|-------------|
| `find` | string | required | Regular expression, anchored to the whole node's source text |
| `replace` | string | — | Template for the quick fix. Omit it to report only |
| `node` | string | `methodInvocation` | Which node kind to match: `methodInvocation` or `propertyAccess` |
| `message` | string | — | Project-specific explanation appended to the diagnostic |
| `in` | list of globs | everywhere | Limits where the entry applies |
