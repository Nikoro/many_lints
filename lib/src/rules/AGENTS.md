# Lint Rules — Quick Reference

This directory contains lint rule implementations. Each rule extends `ManyLintsRule` (this package's `AnalysisRule` subclass) and uses the `SimpleAstVisitor` pattern.

**Full implementation guides:** [rules-patterns.md](../../../.agents/skills/new-lint/rules-patterns.md) | [rules-recipes.md](../../../.agents/skills/new-lint/rules-recipes.md)
**To create a new lint rule:** use the `/new-lint` skill

## Rule Pattern

Every rule follows: `ManyLintsRule` + `_Visitor extends SimpleAstVisitor` + `registerManyLintsProcessors()` + `rule.reportAtNode()`.

⚠️ Override `registerManyLintsProcessors()`, **not** `registerNodeProcessors()` — `ManyLintsRule` implements the latter to wire up per-rule `exclude`. Overriding it directly silently disables `exclude` for that rule.

For class prefix/suffix naming rules, use the `ClassAffixValidator` base class — the base type is user configuration (`entries:`), not a constructor argument.

## Key Concepts

- **TypeChecker** (`../type_checker.dart`) — type matching: `fromName()`, `fromUrl()`, `isSuperOf()`, `isAssignableFromType()`
- **Type inference** (`../type_inference.dart`) — `inferContextType()`, `resolveReturnType()`, `isTypeCompatible()`
- **AST helpers** (`../ast_node_analysis.dart`) — `isExpressionExactlyType()`, `maybeGetSingleReturnExpression()`, `firstWhereOrNull`, `enclosingClassDeclaration()`, `hasOverrideAnnotation()`, `negateExpression()`, `buildEveryReplacement()`
- **Hook detection** (`../hook_detection.dart`) — `getAllInnerHookExpressions()`, `maybeHookBuilderBody()`
- **String distance** (`../text_distance.dart`) — `computeEditDistance()`
- **State base classes** (`../state_base_classes.dart`) — `isStateElement(rule, element)` replaces a hand-rolled `TypeChecker.fromName('State', packageName: 'flutter')` in the 14 rules that only apply inside a `State`. Adds the `state_base_classes` option, which names *non-`State`* bases to treat as state; an intermediate `BaseState<T>` extending `State` already works via `isSuperOf` and needs no config
- **Disposal utils** (`../disposal_utils.dart`) — `findCleanupMethod()`, `cleanupMethods`, `resolveCleanupMethods(rule)` (shared by dispose_fields + dispose_provided_instances). Returns a `List`, not a `Set`: order is the priority used when a type declares several cleanup methods. Resolve once per callback and pass into **every** collector — using the configured list for detection but not recognition turns an option into a false positive
- **Widget helpers** (`../flutter_widget_helpers.dart`) — `FlexAxis` enum (shared by prefer_spacing + use_gap)
- **Riverpod checkers** (`../riverpod_type_checkers.dart`) — `notifierChecker` TypeChecker (shared by avoid_notifier_constructors + dispose_provided_instances)
- **Rule base** (`../many_lints_rule.dart`) — `ManyLintsRule` applies `exclude`, `include` and `message` for **every** rule automatically by intercepting `set reporter` (the single field all `reportAt*` methods funnel through): a null-listener reporter for excluded/not-included files, and a message-appending subclass when `message:` is set. No visitor-level guard needed, so a rule with several registered callbacks cannot leak diagnostics from one it forgot
  - ⚠️ To rewrite (not just drop) diagnostics you must **subclass `DiagnosticReporter`** and override the public `reportError` — its listener field is private with no accessor, and `AnalysisRule.reportAt*` delegate to private non-virtual helpers, so neither can be wrapped
- **Rule config** (`../rule_config.dart`) — `exclude` globs + free-form options from `many_lints.yaml` (or a top-level `many_lints:` section in `analysis_options.yaml`; the file wins, no merge). Read mode options via `rule.config.boolOption(...)` / `intOption(...)` / `stringListOption(...)` / `nameSetOption(...)` / `patternOption(...)` / `entriesOption(...)`, resolved per file. Follow the fixed key vocabulary (`max_<unit>`, `min_<unit>`, `ignore_<singular>`, `ignored_<plural>`, `name_pattern`, `<plural>` replaces, `additional_<plural>` appends) — do not invent new key shapes. The analyzer cannot carry per-rule options itself; see [config-cookbook.md](../../../.agents/skills/new-lint/config-cookbook.md)
  - ⚠️ **"The rule already does that" argues *for* an option, not against it.** If the current behaviour is the narrow one, the option widens (`report_enums`, `only_same_name: false`, `additional_methods`, `state_base_classes`) and the default still reproduces today's results. "Prefer quieter" governs the *default*, not the direction an option may move. Reject only when there is no dimension to act on at all, and say which one is missing
  - ⚠️ Never cache resolved config on the rule or in a visitor constructor — rule instances are long-lived singletons reused across package roots, so cached config leaks between packages. Read it inside the callback.
  - ⚠️ If an option feeds the diagnostic message, make `diagnosticCode` a **getter** that rebuilds the `LintCode`; one built once in the constructor keeps advertising the default (see `ClassAffixValidator`). But when the value varies **per diagnostic** rather than per file, keep one `static const` code and pass the value via `arguments:` — a per-access `LintCode` breaks fix registration, which keys on the code object.
  - `rule.relativePath` gives the current file's path relative to the package root, `/`-separated, for options that scope by glob (`in:` on a banned entry). Captured with `config` in the reporter setter, so it is likewise only valid inside a callback. Do **not** substitute `RuleContext.isInLibDir`/`isInTestDirectory` — they come from the *defining* unit and misreport for part files
  - Configurable today (52 of 154 rules): every rule takes `exclude`/`include`/`message`; rule-specific options live on `avoid_collection_methods_with_unrelated_types`, `avoid_commented_out_code`, `avoid_missing_completer_stack_trace`, `avoid_not_encodable_in_to_json`, `avoid_passing_async_when_sync_expected`, `avoid_shadowed_extension_methods`, `avoid_unrelated_type_casts`, `avoid_unremovable_callbacks_in_listeners`, `check_for_equals_in_render_object_setters`, `avoid_default_tostring`, `avoid_duplicate_bloc_event_handlers`, `avoid_duplicate_collection_elements`, `avoid_hooks_outside_build`, `avoid_misused_hooks`, `avoid_only_rethrow`, `avoid_returning_widgets`, `avoid_unassigned_stream_subscriptions`, `check_is_not_closed_after_async_gap`, `emit_new_bloc_state_instances`, `prefer_class_destructuring`, `prefer_container`, `prefer_immutable_bloc_state`, `prefer_private_named_parameters`, `prefer_shorthands_with_constructors`, `prefer_single_widget_per_file`, `prefer_spacing`, `prefer_switch_expression`, `prefer_switch_with_enums`, `require_atomic_async_updates`, `use_class_prefix`, `use_class_suffix`, `use_gap`, `dispose_fields`, `dispose_provided_instances`, the 14 `State` rules (`state_base_classes`), and the six pure-policy rules (`avoid_banned_imports`/`_exports`/`_types`/`_names`/`_annotations`, `banned_usage`)
- **Reporting** — `reportAtNode()`, `reportAtToken()`, `reportAtOffset()`, with `{0}` placeholder interpolation
- **Analyzer 14.1.0** — use `node.declaredFragment?.element` (not deprecated `.element`), `node.body` (not `.members`), `namePart.typeName` for class/enum names; `ClassBody`/`EnumBody` are sealed (use `BlockClassBody`/`BlockEnumBody` to access `.members`); use `is DynamicType` (not `identical`) since 12.1.0 allows aliases for `dynamic`/`Never`/`void`. Since 13.0.0: `NamedExpression` → `NamedArgument` (NOT an `Expression`; `.name` is a `Token`, value is `.argumentExpression`), `ArgumentList.arguments` is `NodeList<Argument>` (sealed: `Expression` | `NamedArgument`), `DefaultFormalParameter`/`SimpleFormalParameter` → `RegularFormalParameter` with `.name`/`.type`/`.defaultClause` directly on `FormalParameter`, `Label.name` is a `Token`, `MethodDeclaration.isAbstract` → `!isComplete`, `ExtensionTypeDeclaration.primaryConstructor` → `namePart`
